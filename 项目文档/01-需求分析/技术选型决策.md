# ADR-001：技术栈与系统形态

- 状态：已确认
- 确认日期：2026-11-11（Europe/Berlin）
- 适用题目：02 宠物门店的预约、接待、服务与取消退款

## 决策

采用以下技术基线：

```text
Go
├── Web：Gin
├── ORM：GORM
├── 数据库：MySQL 8.0 / InnoDB
├── 页面：html/template（HTMX 可选）
├── 测试：testing、httptest、testify
└── 运行：Docker Compose
```

系统采用模块化单体，不拆分业务微服务。模拟支付渠道作为独立 HTTP 进程运行，以便受控演示支付和退款的成功、失败、超时/待确认及重复通知。

本题验收完成后可扩展接入真实支付宝。当前实现需预留支付渠道接口，但真实支付宝 SDK、商户签约、密钥配置、沙箱/生产回调及上线备案不属于本题交付范围。

## 选择理由

1. Gin 和 GORM 能控制一天内的交付成本，同时保留清晰的 HTTP、业务服务和持久化边界。
2. MySQL 8.0/InnoDB 支持事务、唯一约束、条件更新和行级锁，能够验证并发抢位及取消/核销竞争。
3. `html/template` 足以实现题面要求的最小业务页面，避免额外前端构建链。
4. 模块化单体便于一次部署、测试覆盖率统计、版本追踪和演示完整闭环。

## 强制约束

- 金额均使用整数分，Go 使用 `int64`，MySQL 使用 `BIGINT`。
- 关键表使用 InnoDB，并建立必要的外键、唯一索引和普通索引。
- 数据库使用严格 SQL 模式。
- 时间以 UTC 持久化，按已确认的门店时区 `Asia/Shanghai` 进行业务判断和显示。
- 关键并发流程必须由事务加条件更新、乐观锁或 `SELECT ... FOR UPDATE` 保证。
- 支付请求号、渠道通知号、退款业务号等幂等键必须由数据库唯一约束兜底。
- 预约业务只能依赖统一支付渠道接口，不能直接依赖模拟服务或支付宝 SDK。至少抽象支付发起、支付查询、退款发起、退款查询和异步通知验签/解析能力。
- 支付记录保存渠道类型和渠道交易号，为后续支付宝接入保留扩展点；密钥不得进入仓库、日志、截图或会话导出。
- MySQL 集成测试用于验证真实事务和锁行为，不用 SQLite 模拟这些行为。
- 不引入 Redis、消息队列、微服务或完整前端 SPA，除非后续出现有证据的必要性并经学生确认。

## 预期模块边界

```text
internal/
├── auth/           # 预置身份、角色和门店归属
├── slot/           # 时段发布与查询
├── booking/        # 预约、占位、容量和超时关闭
├── payment/        # 支付、通知幂等和晚到支付
├── cancellation/   # 提前取消、临近取消申请和审核
├── refund/         # 退款及失败重试
├── fulfillment/    # 核销、服务开始和完成
├── closing/        # 未到店与日清
└── platform/       # 数据库、时钟、审计和通用错误
```

模块是代码职责边界，不代表独立服务。跨模块状态变化由应用服务在一个数据库事务中协调。

## 未采用方案

- PostgreSQL：能够满足要求，但本项目已确认使用 MySQL。
- SQLite：不作为关键并发和部署数据库，避免锁语义与正式环境不一致。
- Fiber：本题无需其性能特点，优先使用标准 `net/http` 生态兼容性更好的 Gin。
- React/Vue：页面交互规模较小，收益不足以抵消构建和测试成本。
- 微服务：增加分布式事务、部署和证据管理成本，不符合单题边界。

## 后续影响

- 原型需覆盖用户、前台、客服、店长四类页面，但无需确定数据库实现细节。
- 任务规划需单列 MySQL 迁移、唯一约束、并发集成测试和模拟支付服务任务。
- 自动流水线需启动 MySQL 8.0 服务后执行集成测试和覆盖率门禁。

## 后续支付宝扩展边界

后续真实接入建议新增 `AlipayProvider`，与本题的 `MockPaymentProvider` 共同实现统一接口。接入时还需单独完成：

1. 支付宝商户及应用开通、签约产品和回调域名配置；
2. 应用私钥、支付宝公钥或证书的安全托管与轮换；
3. 服务端创建支付、异步通知验签、主动查询、退款和退款查询；
4. 金额、商户订单号和应用身份核验，防止仅凭“支付成功”字段确认预约；
5. 通知重放、乱序、超时、查询补偿及关闭预约后晚到支付的真实退款处理；
6. 沙箱验证、生产小额验证、监控告警和对账。

接入真实支付宝时不得改变已确认的预约、取消、履约和日清规则，只替换支付渠道适配层并补充渠道特有测试。
