# 题目 02 AI 使用说明

## 1. 工具与模型

- 主要工具：Codex 桌面应用、终端、Git、Docker、GitHub MCP 与 GitHub API。
- 模型：当前项目材料未取得可独立核验的精确模型版本字段，按题面要求标为“不可获取”，不根据界面外信息猜测。
- AI 角色：需求整理、原型与代码生成、测试执行、缺陷分析、文档和 Git/CI 操作。
- 学生角色：确认需求假设、选择技术栈和数据库、检查页面效果、指出乱码/静态提示/支付入口等问题、确认流程例外、授权 PR 和合并、决定不部署。

## 2. 各阶段分工

| 阶段 | AI 完成 | 学生审核/决定 |
| --- | --- | --- |
| 需求与假设 | 从题面整理 R-01～R-12、S-01～S-05 和 A-01～A-12 | 明确 12 项全部按推荐确认 |
| 原型 | 制作角色页面、交互逻辑和自动测试 | 多次指出页面乱码、只有提示没有真实效果、支付入口和时间状态问题 |
| 技术与计划 | 建议 Gin/GORM/MySQL/html/template、模块化单体和阶段任务 | 确认 MySQL、阶段顺序、后续支付宝计划 |
| 开发 | 实现预约、支付、取消退款、履约、未到店、日清和真实页面 | 要求中文页面、真实可操作、自测通过再继续 |
| 测试 | 开发自测；另用独立测试 Agent 执行 MySQL、并发、race 和覆盖率 | 逐阶段回复确认后才继续 |
| 缺陷修复 | 修复 T31 死锁和 T33 错误泄露，并重新测试 | 允许教师缺少编号时使用透明无编号流程，不允许伪造 |
| 验收 | 独立验收 Agent 按原题面执行 T33/T34 | 学生确认继续 T35～T38 |
| Git/CI | 配置 Actions、main 保护、草稿 PR、合并及 main 再门禁 | 明确确认创建 PR 和执行合并 |
| 部署 | 识别缺少教学环境并说明所需条件 | 明确决定“不用部署了” |
| 最终材料 | 汇总实际 Skill、AI、缺陷、版本和缺口 | 仍需学生导出平台完整聊天、录制视频并完成群提交 |

## 3. 有证据的 AI 错误与学生纠正

1. 原型部分按钮最初只有点击提示，学生要求“真实能用并自己测试”，之后补成可持久化交互并增加自动测试。
2. 页面曾出现乱码，学生用截图指出后修正编码和中文状态展示。
3. 预约后支付入口、时间和状态不清楚，学生指出后增加直达支付中心、北京时间和中文资金状态。
4. Codex 尝试创建 PR 时只弹出交互表单，并未真正创建；学生截图说明“没看见”，随后改用 GitHub API，实际生成 PR `#1`。
5. 自动化测试发现中文 workflow 文件名未被 GitHub Actions 登记，AI 没有把零运行当作成功，改为 `ci.yml` 后产生真实运行。

## 4. AI 自检发现并修正的问题

- 数据库有效预约和待审核取消最初缺少唯一约束；
- 默认隔离级别下容量读可能超卖；
- 支付与通知、占位过期与预约创建存在反向锁序；
- 履约幂等查询可能读取旧快照；
- 已完成状态曾漏计容量；
- T31 独立测试发现真实死锁；
- T33 独立验收发现 callback URL 和网络错误泄露；
- 修复增加代码后曾导致核心包覆盖率回落，补测后恢复门禁。

证据位于 `项目文档/05-Skill记录/`、`06-开发记录/`、`07-独立测试/` 和 `08-独立验收/`。

## 5. 学生实际审核边界

能够从会话和提交确认的学生审核包括：框架、MySQL、假设、页面可用性、中文状态、流程顺序、GitHub 仓库、PR、合并和不部署决定。无法从现有材料证明学生逐行审核了全部 Go 代码，因此不作该声明。

## 6. 未完成和限制

- 平台尚未提供完整聊天的一键导出文件；当前仓库只有阶段记录和可核查摘要，不冒充逐字会话。
- 精确模型版本字段未进入项目证据，标为不可获取。
- 教师未提供真实工作项/meegle、缺陷渠道、部署目标。
- 用户决定不部署；没有正式地址、上线冒烟或回退结果。
- 视频讲解和班级群提交必须由学生本人完成，AI 不能代替。
