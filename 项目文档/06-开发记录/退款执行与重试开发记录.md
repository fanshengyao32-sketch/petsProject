# T19 退款执行与重试开发记录

## 完成内容

- 客服退款处理台 `/support/refunds`。
- 待退款、处理中、待确认、失败、成功五种独立状态。
- 每次退款尝试拥有独立请求号和顺序号。
- 渠道失败和超时可由客服重试。
- 成功后重复操作幂等，不产生第二次退款。
- 退款失败不恢复已取消、已关闭或其他预约状态。
- 用户支付中心可查询最新退款状态。
- 模拟渠道支持成功、失败和超时三种退款结果。

## 页面修正

- 用户端、支付中心、客服端和店长端不再直接展示英文内部错误。
- 未登录访问业务页面重定向到身份选择页；API 仍使用 JSON 401/403。
- 重复预约提示改为“该宠物在这个时段已有一笔有效预约，请勿重复预约”。

## 状态与事务

退款执行先锁预约、退款单和原支付单，再创建 `refund_attempts` 事实。渠道调用返回后，以事务更新本次尝试与退款单；失败或未知只改变退款状态，不改变预约状态。成功退款记录 `refunded_at`，重复执行直接返回成功事实。

## 当前边界

本阶段仍使用模拟支付渠道。支付宝沙箱会实现相同 `Provider` 接口，不改变预约、取消和退款状态机。
