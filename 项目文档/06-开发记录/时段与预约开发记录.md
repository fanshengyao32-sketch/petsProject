## 实际缺陷与修复

### DEV-T15-01：并发容量超卖

- 首次真实 MySQL 用例：4 名主人并发争抢容量 3，实际 4 个请求均成功。
- 原因：事务先执行普通幂等查询，建立了 `REPEATABLE READ` 快照；等待时段行锁后再使用普通 `COUNT`，仍可能读取旧快照，遗漏刚提交的预约。
- 修复：保留时段行锁，并把容量读取改为对占位预约执行 `SELECT ... FOR UPDATE` 的锁定读。
- 复测：3 个成功、1 个 `ErrCapacityFull`，连续重复执行通过；Linux `-race` 通过。

### DEV-T15-02：并发幂等可能被误判为重复宠物

- 首次真实 MySQL 用例：同一幂等键并发创建时，部分请求返回 `ErrDuplicateActive`。
- 原因：同一条插入同时可能冲突两个唯一索引，MySQL 不保证先报告哪个索引。
- 修复：唯一冲突后先回滚事务，再按 `(owner_id, request_key)` 查询；存在则返回同一预约，不存在才判定为有效预约重复。
- 复测：4 个并发请求均成功返回同一个预约 ID；不同请求键仍被有效预约唯一约束拒绝。

### DEV-T14-01：预置中文数据乱码

- 页面现象：HTML 固定文字正常，但宠物名称和品种显示为 `å.../æ...` 形式乱码。
- 原因：数据库与 SQL 文件均为 UTF-8，但 Docker 内 `mysql` 客户端导入连接默认是 `latin1`，UTF-8 字节被当作 Latin-1 字符再次编码。
- 修复：`000002_seed.sql` 开头显式执行 `SET NAMES utf8mb4`；新增幂等迁移 `000003_fix_seed_encoding.sql` 修正已初始化开发库中的门店、项目、用户和宠物中文字段。
- 复测：当前页面显示“团子（比熊）”且不含乱码；空数据库完整执行 001～003 后，`团子` 的十六进制字节为正确的 `E59BA2E5AD90`。

### DEV-AUTH-01：多标签页演示身份互相覆盖

- 页面现象：用户页与店长页在同一浏览器的两个标签页打开后，后登录的角色覆盖全局 `pet_session`，另一个标签页刷新时返回 `ROLE_FORBIDDEN`。
- 原因：浏览器标签页共享同一域名 Cookie，首版演示登录只使用一个 Cookie 名称。
- 修复：按角色使用 `pet_session_owner`、`pet_session_manager` 等独立 HttpOnly Cookie；`RequireRole` 只加载当前接口要求的角色 Cookie，同时保留旧 Cookie 的兼容读取并在新登录时清除旧 Cookie。
- 权限约束：没有取消或放宽 `RequireRole`，请求参数仍不能指定用户身份；未知、伪造或错角色会话仍被拒绝。
- 复测：同一个 Cookie 容器同时保存用户和店长会话后，`/owner` 显示林小满、`/manager` 显示许岚，两个页面均为 HTTP 200。
