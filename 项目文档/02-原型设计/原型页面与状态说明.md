# 题目 02——原型页面与状态说明

## 1. 原型定位

- 页面入口：`交互原型.html`
- 运行逻辑：`原型运行逻辑.js`
- 类型：可操作的高保真浏览器原型
- 用途：确认角色入口、业务信息、主要操作、成功/失败提示和日清口径
- 数据性质：预置演示数据与用户操作结果保存在浏览器 `localStorage`，刷新页面后仍可查询；页面提供“重置演示数据”操作
- 打开方式：直接用浏览器打开，或在本目录启动静态 HTTP 服务

本原型可真实操作并联动展示创建时段、预约占位、支付、取消、审核、退款重试、核销、服务履约、未到店、晚到支付异常和日清结果，但不包含 Go 服务、MySQL、真实鉴权、多人并发控制或模拟支付 HTTP 调用。这些服务端能力只能在后续开发和测试阶段形成证据，不能把浏览器本地保存冒充数据库持久化。

本题开发阶段使用可控模拟支付服务，以满足成功、失败、超时/待确认和重复通知的验收要求。系统架构预留统一支付渠道接口；真实支付宝作为本题验收完成后的扩展，不在当前原型或单日交付范围内。

门店业务时区现已确认为 `Asia/Shanghai`；原型中的教学时间均应理解为北京时间。正式实现以 UTC 持久化，并在服务端依据门店时区判断取消、时段和日清边界。

## 2. 角色页面

| 页面 | 主要信息和操作 | 对应需求 |
| --- | --- | --- |
| 宠物主人 | 选择时段、查看容量、提交预约、支付、取消、查看取消审核/退款/服务结果 | R-02～R-06、R-11 |
| 前台与服务 | 查询预约、显示禁止核销原因、核销、服务开始、服务完成 | R-07、R-08、R-11 |

## 3. 页面状态说明

### 3.1 用户预约

- 时段卡片展示起止时间、容量和是否可选。
- 待支付预约显示 5 分钟倒计时、支付和主动取消入口。
- 已确认预约允许发起取消；演示弹层说明取消政策并要求原因。
- 取消待审核明确展示“仍占名额、禁止核销”。
- 已完成预约提供履约结果入口。

### 3.2 前台与服务

- 已确认记录可核销。
- 取消待审核记录显示具体禁用原因。
- 非本店预约显示权限原因，不提供可点击核销入口。
- 核销后才能登记服务开始，服务开始后才能完成。
- 页面提示重复操作不得重复记收入，但真实幂等需后续接口和数据库测试证明。

### 3.3 客服

- 待审核取消显示距开始时间、用户原因和当前占位情况。
- 批准后显示取消生效、释放名额和发起退款。
- 拒绝后显示预约恢复可核销，审核记录仍保留。
- 退款失败记录显示渠道原因、尝试次数和重试入口；重试成功不改变已取消事实。

### 3.4 店长日清

- 成功收款、已退款、退款待处理和完成服务收入分开显示。
- 时段结果分为有效、完成、取消和未到店。
- 时段结束未核销记录提供“标记未到店”，并明确不自动退款。
- 资金明细能够区分已收、已退、未退和完成收入，避免把所有付款计为完成服务。

## 4. 五组演示入口

原型顶部提供五个场景按钮，并自动切换到主要角色页面：

| 场景 | 主要点击路径 | 原型可见结果 |
| --- | --- | --- |
| S-01 正常接待 | 用户支付 → 前台核销 → 服务开始 → 完成 | 状态按顺序变化，完成收入只出现一次 |
| S-02 名额循环 | 查看满额时段 → 取消待支付预约 | 显示名额释放说明；真实并发不在原型实现 |
| S-03 取消分支 | 客服批准/拒绝 → 退款失败重试 | 取消和退款状态分别展示 |
| S-04 现场冲突 | 查看待审核禁止核销、跨店禁用和重复操作说明 | 冲突的唯一结果需后续并发测试证明 |
| S-05 收店核查 | 查看四类记录 → 标记未到店 → 查看资金明细 | 分类和金额口径可核对 |

## 5. 失败与异常状态

- 时段已满：预约按钮禁用并显示“名额已满”。
- 取消待审核：核销按钮禁用并解释原因。
- 非本店预约：操作按钮禁用并显示无权限。
- 退款失败：保留失败代码、尝试次数和重试操作。
- 表单缺少取消原因：页面提示填写原因。
- 重复核销/完成、重复通知和并发竞争：原型只展示预期提示，必须由后续实现和测试提供真实证据。
