# 题目 02——原型需求追踪

| 需求 | 原型位置 | 展示或交互 |
| --- | --- | --- |
| R-01 时段发布 | 店长工作台 | “发布时段”弹层，展示起止时间和固定容量 |
| R-02 预约唯一性与容量 | 用户工作台 | 时段容量、已满禁用、提交占位入口 |
| R-03 待支付占位 | 用户“我的预约” | 5 分钟倒计时、付款和主动取消 |
| R-04 支付及晚到支付 | 用户“我的预约” | 支付后转已确认；晚到支付留待实现阶段异常页细化 |
| R-05 取消政策 | 用户取消弹层、客服审核表 | 提前取消提示、临近取消批准/拒绝 |
| R-06 退款 | 客服退款跟进 | 失败原因、重试次数、成功结果 |
| R-07 履约 | 前台与服务工作台 | 核销→服务开始→完成的顺序按钮和时间线 |
| R-08 并发唯一结果 | 前台禁用态和提示 | 展示预期结果；真实竞争由测试证明 |
| R-09 未到店 | 店长待收尾事项 | 填写原因的交互在实现时补全，原型展示标记结果和不退款口径 |
| R-10 日清 | 店长概览、时段结果、资金明细 | 四类指标和逐笔核查 |
| R-11 权限 | 用户身份、前台跨店禁用、角色工作台 | 身份上下文和拒绝原因 |
| R-12 审计与异常 | 各状态提示、客服失败详情 | 原型展示证据位置，持久化需实现验证 |

## 待评审发现

1. 门店业务时区已确认为 `Asia/Shanghai`，正式实现以 UTC 持久化并按北京时间判断业务边界。
2. 店长标记未到店必须填写原因；可操作原型已增加原因弹层并通过自动测试。
3. 晚到支付成功后的异常退款在客服异常资金区域展示；预约保持关闭，相关路径已通过原型自动测试。
