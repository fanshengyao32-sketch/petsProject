## 3. T33 原攻击运行态复测

在独立端口 `127.0.0.1:18081` 启动当前提交的 `cmd/mock-payment`，使用无真实秘密的原攻击形式：

```json
POST /v1/payments
{
  "request_no": "T34-T33-DEF01",
  "booking_no": "BK-T34-T33-DEF01",
  "amount_cents": 9900,
  "scenario": "success",
  "callback_url": "http://127.0.0.1:1/internal-callback?token=t33-sensitive-marker"
}
```

创建支付返回 200。随后执行：

```json
POST /v1/payment-notifications
{"request_no":"T34-T33-DEF01","duplicate":false}
```

实际响应：

```text
HTTP 502
{"error":"NOTIFICATION_DELIVERY_FAILED","message":"支付结果通知发送失败，请稍后重试"}
```

响应内容逐项断言：

| 禁止内容 | 是否出现 |
| --- | --- |
| 完整 callback URL | 否 |
| `127.0.0.1:1` host/port | 否 |
| `t33-sensitive-marker` 查询参数标记 | 否 |
| `internal-callback` 路径 | 否 |
| `dial tcp` | 否 |
| `connection refused` | 否 |

响应 body 与预期稳定 JSON 精确相等。
